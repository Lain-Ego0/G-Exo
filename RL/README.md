## 部署目录（AI总结整理）

### `RL/deploy/`

完整的 TCN + Actor ONNX 部署包，包含：

- TCN 和 Actor ONNX 模型；
- C++ 推理代码；
- 模型配置；
- 参考回放和 runtime 测试；
- CMake 构建文件；
- 模型导出工具。

### `RL/deploy_tcn_pd/`

TCN + PD 保险部署包，用作主策略异常时的备用控制方案。

### `control/`

面向实际外骨骼控制程序的集成代码：

```text
control/motor/              # RS02 电机协议、CAN 和电机测试
control/deploy/             # TCN + Actor 控制运行时
control/deploy/tcn_pd/      # TCN + PD 备用运行时
control/config/             # 电机侧配置
control/launch/             # ROS2 启动文件

control/package.xml         # ROS2/CMake 工程配置
```

```text

```

其中 `1.hardware/G-exo_URDF/` 保存外骨骼 URDF，属于硬件资产，不属于 RL 训练逻辑。

## 训练历程与个人心得

在刚刚敲定使用RL进行外骨骼训练时，队长给出的建议方案是使用opensim作为仿真底座进行训练。在大概4-5天的时间里，笔者比较快地进行了调研和思考，写出了第一版代码，实现了仿真的基本设计。
选择opensim的主要原因其实并不复杂，主要是因为这是一套比较主流的仿真方案，并且可以对人体肌肉、关节等部分进行比较准确的模拟。但是，在进行了几天的尝试后，opensim这个方案逐渐显露出了问题，主要体现为：1.opensim的控制是各肌肉层面的，它并不自带一个人的身躯整体的行走策略。2.opensim本身作为一个仿真器，其各项参数以及训练便利程度，均不如MuJoCo这种通用仿真器。如果后者仅仅是过程繁琐麻烦，那么前者是紧急工况下无论如何都没办法接受的问题。因此，我们放弃了opensim。
紧接着，我们转向了MyoSuite，这是一个基于MuJoCo的肌肉动力学模型，同时它拥有一个基本的行走策略，这样，我们不需从头开始训练行走策略，只需要考虑如何将策略与外骨骼控制策略进行整合即可。然而，该模型自带的行走策略是一个十分基础的行走策略，如果想要进一步训练外骨骼策略，我们需要在这个策略的基础上进一步训练，以实现一个较好的效果。显然这在进度紧张的情况下是难以实现的。
紧接着我们转向了Kinesis，这同样是一个基于MuJoCo的运动/肌肉控制框架，并且有一个更为完善的行走策略，笔者此时选择冻结这个策略，然后在此基础上正式开始进行外骨骼RL策略训练。
在训练过程中，奖励指标是首先需要考虑的问题。考虑到外骨骼的主要使用目标是省力，笔者将整个控制框架拆分为两个部分：第一，要学会短时预测人体行走策略（这一部分由外部TCN而非RL策略实现，不计入奖励）；第二，策略要学会如何控制电机实现下一微观时间步长下的省力运动。因此，奖励指标主要由两部分组成：肌肉的省力（以激活计算）与人体主动力矩的减小进行计算，其他基本为正则项。
但是在训练过程和最终指标表中，可以通过观察发现，尽管有多次调整，例如变换权重，调整计算方式等方式，并且在几次训练中尝试引入无外骨骼策略的基线比对作为一个附加项，但是最终的训练指标仍然没有明显提升。在多次尝试和重复后，笔者认为，这是Kinesis本身存在的结构性问题。因为这个行走策略尽管可以与外部扰动互动，但是该互动最终基本会以人体重新回到固定轨迹为常见结果，这导致我们无法连续地对人体施加力矩，以实现省力效果。
举个例子，在训练过程中，若Kinesis原策略为髋关节无任何外伸，外骨骼可能会让髋关节外伸0.1rad，但是Kinesis本身会倾向于让髋关节从该变化回到无外伸，在这个对抗过程中，外骨骼的省力效果将无法体现，更别提连续发力以实现一个连续的省力策略了。
另外，还有一个问题在于计算基准。前文提到，主要的奖励指标为以肌肉激活计算的省力指标和关节主动力矩的减小。但是，同一个动作所涉及到的肌肉行为未必是相同的，可能有的肌肉群在放松，有的肌肉群却在收缩，即使使用全局平均的方法来看，也很难准确量化省力效果。
由于结构性问题，笔者再次转向，最终选择了MyoAssist作为主线训练框架，这是一个基于 MyoSuite/MuJoCo 的肌肉骨骼环境及人体控制策略。首先是它所调动的肌肉群会略少一点，其次是它具有一个原生的较为完善的行走策略，最后是可以和外骨骼实现较为柔性的配合。
不过，此时由于工期已接近结束，笔者并未能训练出较好的策略，最终只赶工出来一个理论上较优的策略，不过至少，它的确能实现省力。
在赛事结束后复盘笔者发现，这本质是一个多策略融合互动的问题，关键在于，如何实现经由现有的一定程度上可变的策略来训练一个针对前者的优化策略——而且这个优化策略还是从外部施力的。在这个基础上就要考虑，如何针对二者的融合做一个限制或者结合。另外，这里面的另一个问题是，如何在保证双方有效性的前提下，构建一个马尔科夫链，哪怕是不可完全采样的。在这个问题上，笔者暂时没有特别多的思路，需要进一步地思考和探索。
另外一个问题是我们缺少更加完善的肌肉行走策略，根据搜索到的几篇论文来看，大部分可以实现双髋关节或双踝关节的行走策略都基于课题组自搭的肌肉模型和完善的行走策略，甚至有课题组针对人体上百块肌肉进行了建模仿真，接下来再使用该模型训练行走策略，最后实现外骨骼策略的训练——而笔者可以搜索到的所有公开行走策略都没有如此完善。
总的来说，在此次项目的训练过程中，尽管策略不慎满意，但是笔者的确对于RL训练和外骨骼工程有了更深的认识，在这个过程中也更深刻地感受到了physics与AI的结合，有了自己的实践经验。
