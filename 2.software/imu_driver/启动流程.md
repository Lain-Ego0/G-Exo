# 四 IMU 系统重启后启动流程

> 服务器: 192.168.11.66 (Bianbu 4.0.1, riscv64, ROS2 Humble)
> 硬件: 4 块 Epson G354PDH0 IMU 载板 (CH343 USB → /dev/ttyACM0~3)
> 名称: A1 / A2 / B1 / B2 (已通过 udev 按 CH343 硬件序列号绑定, 换口/拔插不乱名)

---

## 0.5 udev 硬件绑定 (只装一次)

4 块板已按 **CH343 芯片出厂序列号** 绑定固定设备名, 换 USB 口/拔插都不会乱名:

| 固定设备名 | CH343 序列号 | Epson 序列号 |
|-----------|-------------|-------------|
| /dev/imu_A1 | 5C38170227 | 00001368 |
| /dev/imu_A2 | 5C38170221 | 00001095 |
| /dev/imu_B1 | 5C38170222 | 00002736 |
| /dev/imu_B2 | 5C38170220 | 00011726 |

规则文件: `/etc/udev/rules.d/99-imu.rules` (已安装)。若重装系统需恢复:

```bash
sudo cp ~/imu-udev.rules /etc/udev/rules.d/99-imu.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty
```

验证: `ls -l /dev/imu_*` 应看到 4 个链接。

## 4. 启动自动检测守护进程 (核心步骤)

```bash
ros2 launch ess_imu_driver2 imu_auto_launch.py names:="A1 A2 B1 B2"
```

启动后终端会持续打印 (约每 1 秒一次):

```
[imu_auto_detect] 19:13:57 + 检测到 /dev/ttyACM0 -> 节点 A1_node, 话题 /A1/ahrs, frame A1_link
[imu_auto_detect] 19:13:57 当前 4 个 IMU 在线 | 话题: /A1/ahrs /A2/ahrs /B1/ahrs /B2/ahrs
```

> 这个终端保持运行, 不要关闭。**插拔 IMU 会自动增删对应节点, 无需重启。**

### ✅ 默认配置 (2026-08-01 优化后)

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 姿态话题 /A1~B2/ahrs | **开** | Mahony 姿态解算已**内嵌进驱动节点**, 无需独立进程 |
| 原始数据 /A1~B2/data_raw | **关** | `publish_data_raw:=false`, 需要时再开 |
| 温度 /A1~B2/tempc | **关** | `publish_temperature:=false`, 需要时再开 |
| 姿态发布频率 | **200 Hz** | `imu_dout_rate:=9` (4=125Hz, 8=400Hz) |
| 独立 mahony 进程 | **不再启动** | 姿态算法已内嵌驱动, `enable_mahony` 不再需要 |

### 常用变体

| 需求 | 命令 |
|------|------|
| 开启原始数据+温度 | 加 `--publish-data-raw true --publish-temperature true` 或 launch 参数 `publish_data_raw:=true publish_temperature:=true` |
| 调整姿态频率 (如 400Hz) | `imu_dout_rate:=8` (launch) 或 `--imu-dout-rate 8` (脚本) |
| 只识别指定名称的板子 | `names:="A1 A2 B1 B2"` |
| 第 5 块以后继续用字母 | `names:="A1 A2 B1 B2 C1 C2"` (不写则自动用 imu4, imu5...) |
| 调 mahony 参数 | 加 `mahony_kp:=1.0 mahony_ki:=0.005` (传给内嵌解算) |

## 5. 验证数据 (新开一个终端)

```bash
source /opt/ros/humble/setup.bash

# 查看话题 (默认只有姿态 + 系统话题)
ros2 topic list

# 查看姿态频率 (应为 200Hz)
ros2 topic hz /A1/ahrs

# 查看姿态 (每条应输出四元数)
ros2 topic echo /A1/ahrs --once
```

### 话题与节点对照表 (默认配置)

| 名称 | 设备 | 驱动节点 | 姿态话题 | frame_id | data_raw/tempc |
|------|------|---------|---------|----------|----------------|
| A1 | /dev/imu_A1 | A1_node | /A1/ahrs | A1_link | 默认关闭 |
| A2 | /dev/imu_A2 | A2_node | /A2/ahrs | A2_link | 默认关闭 |
| B1 | /dev/imu_B1 | B1_node | /B1/ahrs | B1_link | 默认关闭 |
| B2 | /dev/imu_B2 | B2_node | /B2/ahrs | B2_link | 默认关闭 |
| (第5个+) | /dev/ttyACM4 | imu4_node | /imu4/ahrs | imu4_link | 默认关闭 |

> 启动后内嵌 mahony 需要约 10~20 秒完成校准采样 (calib 500 + init 200 + warmup 300), 之后才开始输出姿态。

## 8. 停止 / 关机

| 操作 | 方法 |
|------|------|
| 停止算法 | 在守护进程终端按 `Ctrl+C` (自动清理所有子节点) |
| 停止后台管理器 (nohup 方式启动的) | `pkill -f imu_auto_detect.py` 或找到 PID 后 `kill <PID>` |
| 关机 | `sudo shutdown -h now` |
| 重启 | `sudo reboot` |

---

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| `ls /dev/ttyACM*` 没有设备 | 重新插拔 USB; `sudo dmesg | grep -i usb` 看内核日志 |
| 某个姿态话题一直不出 | 拔插对应板子; 查看 `/tmp/imu_XXX.log` |
| 名称分配错乱 | 已由 udev 按 CH343 序列号绑定, 不会乱; 若 `/dev/imu_*` 不存在, 先执行 0.5 节恢复规则 |
| rqt 打开报 pyqt 错误 | 不影响, 用 rqt_topic 等 Python 插件即可 |
| 需要原始数据/温度 | 启动时加 `publish_data_raw:=true publish_temperature:=true` |
| 需要更高频率 | `imu_dout_rate:=8` = 400Hz (G354 支持, 滤波 32 阶满足) |

## 10. 2026-08-01 架构变更记录

1. **data_raw / tempc 默认关闭**: 新增 `publish_data_raw` / `publish_temperature` 参数 (默认 false), 减少 12 个无用话题 (4 板 × data_raw + tempc) 的带宽与 CPU 开销;
2. **Mahony 内嵌**: 姿态解算从独立进程 (`mahony_ahrs_node` + DDS 中转 data_raw) 改为**内嵌进驱动节点** (新增 `src/mahony_embedded.h`), 不再依赖 data_raw 话题中转, 更省资源;
3. **姿态频率提升到 200Hz**: `imu_dout_rate` 默认 4(125Hz) → 9(200Hz), 实测 4 板均稳定 200Hz;
4. **修改的文件**:
   - `src/epson_imu_uart_ros2_node.cpp` — 新增 3 参数 + 内嵌 mahony 调用
   - `src/mahony_embedded.h` — 新建, 内嵌姿态解算类
   - `scripts/imu_auto_detect.py` — 透传新参数, 默认不启动独立 mahony
   - `launch/imu_auto_launch.py` — 参数默认值同步
