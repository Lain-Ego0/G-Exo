## 二、硬件映射：论文 → G-Exo

| 论文组件 | 论文规格 | G-Exo 现有 | 匹配度 | 备注 |
|----------|---------|------------|--------|------|
| **髋执行器** | AK80-9, 9:1, 18Nm峰值 | RS02, 7.75:1, 17Nm峰值 | 🟢 95% | 减速比略低但反驱更优 |
| **膝执行器** | AK80-9, 9:1, 18Nm峰值 | RS02, 7.75:1, 17Nm峰值 | 🟢 95% | 同上 |
| **主控** | Raspberry Pi 4B | Orange Pi 5 Plus (RK3588) | 🟢 110% | 性能远超 RPi4，自带 6 TOPS NPU |
| **推理加速** | NVIDIA Jetson Nano | RK3588 NPU (6 TOPS) | 🟢 105% | 单板完成控制+推理，省去 TCP 通信 |
| **IMU** | 6× IMU（大腿/小腿/足部） | 4× G354（大腿/小腿） | 🟡 70% | 缺足部 IMU，精度影响待评估 |
| **编码器** | AK80-9 内置磁编码 | RS02 内置 14-bit 磁编码 | 🟢 100% | 规格一致 |
| **压力鞋垫** | 垂直 GRF + COP | **无** | 🟡 — | 论文消融：去掉仅降 R² 0.03-0.07 |
| **结构** | 碳纤维 + 3D 打印尼龙 | 全 3D 打印 PETG/尼龙 | 🟡 80% | 刚度稍低但不影响控制算法 |
| **电源** | 论文未详述 | 6S 3000mAh ×2 (22.2V) | 🟢 — | 满足 RS02 供电（≥24V 标称） |
| **通信** | CAN (AK80-9) | CAN (RS02, MIT 协议兼容) | 🟢 100% | 协议兼容 |

### 硬件差异的关键影响评估

| 差异 | 影响 | 缓解方案 |
|------|------|----------|
| 缺足部 IMU ×2 | 失去足部运动学信息，膝力矩估计 R² 可能降 ~0.05 | ① 小腿 IMU 可部分替代足部信息 ② 后续可加装廉价 IMU |
| 缺压力鞋垫 | 失去 GRF/COP 直接测量，髋 R²-0.03, 膝 R²-0.07 | ① 论文已证明 IMU 可间接推断 GRF ② 可选后期加装 |
| 单板计算 | 控制+推理共用 CPU/NPU，需合理调度 | RK3588 8 核 CPU，控制线程绑核 + NPU 异步推理 |
| 3D 打印结构 | 刚度低于碳纤维，力传递效率降低 | 加厚关键部位、填充率提高、后续可选碳纤维管 |

### 3.2 技术选型

| 层级 | 选型 | 理由 |
|------|------|------|
| **OS** | Armbian (Ubuntu 22.04) | RK3588 社区支持最好 |
| **实时内核** | PREEMPT_RT 补丁（可选） | 保证控制线程 100-200Hz 确定性 |
| **控制主循环** | C++17（裸线程 + chrono） | 低延迟、无 GC |
| **IMU 驱动** | [ess_imu_driver2](https://github.com/cubicleguy/ess_imu_driver2) (ROS 2) | 已有调研，支持 G354 |
| **CAN 通信** | SocketCAN + 自定义 MIT 协议库 | RS02 原生 MIT 模式 |
| **TCN 模型训练** | PyTorch 1.13+ (Python) | 论文原版用 PyTorch |
| **模型导出** | PyTorch → ONNX → RKNN | RK3588 NPU 推理链 |
| **NPU 推理** | RKNN Toolkit 2 | Rockchip 官方 NPU SDK |
| **数据记录** | HDF5 (C++ API) 或 CSV | 与训练管线兼容 |
| **可选中间件** | ROS 2 Humble | 方便传感器数据流管理，非必需 |

### 3.3 控制循环时序

```
时刻 t (0ms)
  ├─ 读取 IMU 数据 (SPI, ~0.2ms ×4)
  ├─ 读取 RS02 编码器 (CAN, ~0.5ms ×4)
  ├─ 更新滑动窗口 [t-149, ..., t] 特征矩阵
  ├─ 提交 NPU 推理请求
  │
时刻 t+δ (NPU 推理延迟, 目标 <5ms)
  ├─ 获取 TCN 输出: [τ_hip_total, τ_knee_total]
  ├─ 计算生物力矩: τ_bio = τ_total - τ_exo(t-1)
  ├─ 力矩映射:
  │   τ_cmd_hip = Butterworth(τ_bio_hip × 0.20, 10Hz) + delay 100ms
  │   τ_cmd_knee = Butterworth(τ_bio_knee × 0.15, 10Hz) + delay 50ms
  ├─ 限幅: clamp(τ_cmd, -15, 15) N·m
  ├─ 通过 CAN 发送 MIT 力矩指令
  │
时刻 t+10ms (目标周期 10ms = 100Hz)
  └─ 下一循环开始
```

## 四、TCN 模型设计

### 4.1 输入特征 (单侧腿)

| 特征组 | 传感器 | 通道数 | 说明 |
|--------|--------|--------|------|
| 关节角度 | RS02 编码器 ×2 | 2 | 髋角、膝角（度） |
| 关节角速度 | RS02 编码器（差分） | 2 | 髋/膝关节角速度 |
| 大腿 IMU | G354 | 6 | 3 轴加速度 + 3 轴陀螺仪 |
| 小腿 IMU | G354 | 6 | 3 轴加速度 + 3 轴陀螺仪 |
| **单帧总通道** | | **16** | (vs 论文 ~20+ 含足部+鞋垫) |

> 论文原始有足部 IMU(6) + 压力鞋垫(3-4) ≈ 额外 10 通道，我们减去这些后约 16 通道。

### 4.2 网络架构

```
输入: [batch, window=150, channels=16]
  │
  ├─ Z-score Normalization (均值/标准差 冻结自训练集)
  │
  ├─ TCN Block 1: Conv1d(in=16, out=64, kernel=5, dilation=1) + ReLU + Dropout(0.1)
  ├─ TCN Block 2: Conv1d(in=64, out=64, kernel=5, dilation=2) + ReLU + Dropout(0.1)
  ├─ TCN Block 3: Conv1d(in=64, out=128, kernel=5, dilation=4) + ReLU + Dropout(0.1)
  ├─ TCN Block 4: Conv1d(in=128, out=128, kernel=5, dilation=8) + ReLU + Dropout(0.1)
  ├─ TCN Block 5: Conv1d(in=128, out=256, kernel=5, dilation=16) + ReLU + Dropout(0.1)
  │
  ├─ Global Average Pooling (或取最后帧)
  │
  ├─ FC Head (Hip): Linear(256, 128) → ReLU → Linear(128, 1)
  └─ FC Head (Knee): Linear(256, 128) → ReLU → Linear(128, 1)

输出: [τ_hip, τ_knee]  (N·m·kg⁻¹, 体重归一化)
```

> **关键设计决策**：论文训练髋力矩预测未来 50ms（因为控制器额外延迟），实际 TCN 输出头应包含：
> - 当前膝力矩
> - 未来 50ms 髋力矩
>
> 可通过修改髋输出标签时间偏移实现（训练时标签时间轴前移 50ms）。

### 4.3 超参数（论文最终值）

| 超参数 | 论文最优值 | 搜索范围 | 说明 |
|--------|-----------|----------|------|
| 窗口长度 | 150 帧 (750ms @200Hz) | 50-300 | 平衡历史信息与实时性 |
| 卷积核大小 | 5 | 3-9 | — |
| 膨胀因子 | [1,2,4,8,16] | — | 指数增长扩大感受野 |

## 五、数据采集与训练 —— **核心挑战**

### 5.1 问题：没有 Vicon + 测力台，如何获取 Ground Truth 关节力矩？

论文用光学运动捕捉 (200Hz) + 测力台 (1000Hz) + OpenSim 逆向动力学计算关节力矩作为训练标签。我们没有这套设备。

### 5.2 解决方案（按推荐优先级）

#### 方案 A（推荐首选）：租用高校动捕实验室

| 项目 | 说明 |
|------|------|
| 方式 | 联系本地高校（如深圳大学城、华南理工、哈工大深圳）生物力学/运动科学实验室 |
| 设备 | Vicon / OptiTrack / Qualisys 运动捕捉系统 + 测力台 |
| 时长 | 2-3 天（每人约 1 小时 × 15-20 人 × 28+ 动作） |
| 成本 | 估计 ¥3000-8000 / 天（高校内部价可能更低） |
| 产出 | 完整的 sensor-GT 配对数据集 |
| 优势 | 直接对标论文方法，数据质量最高 |

#### 方案 B（替代）：IMU 运动学 + 简化动力学模型

```
IMU 方向估计
    │
    ▼
OpenSim IMU Inverse Kinematics (标定后精度 ~3-5°)
    │
    ▼
简化地面反力模型 (基于加速度积分估算 GRF，精度 ~0.1 BW)
    │
    ▼
OpenSim Inverse Dynamics → 关节力矩
```

| 优点 | 缺点 |
|------|------|
| 成本极低，仅需现有硬件 | IMU 运动学精度显著低于光学标记点 |
| 可在任意场地采数据 | GRF 估计误差传播到力矩 |
| 数据量可无限扩展 | 最终力矩估计 R² 可能比论文低 0.1-0.2 |

> 已有开源工具支持此路线：OpenSense (OpenSim 的 IMU IK 模块)、IMU-based GRF estimation 相关文献。

#### 方案 C（折中）：混合策略

1. 短期：方案 A 采集 3-5 人的高质量标签数据（覆盖 19 个关键任务）
2. 中期：方案 B 采集 10+ 人的无标签数据，用半监督/自训练扩展
3. 长期：部署后在线采集使用者数据，持续微调

#### 方案 D（探索）：直接使用传感器-电流映射

绕过力矩估计的监督训练，直接端到端：
- 用电机电流（已知执行器力矩）+ IMU + 编码器 → 预测辅助力矩指令
- 用代谢成本/EMG 作为优化信号（RL 或贝叶斯优化）
- 但这不是论文复现，而是替代技术路线

### 5.3 推荐数据采集方案：A+C 混合

```
Phase 1: 高校动捕实验室 (2-3 天)
  ├─ 参与者: 5-8 人 (自己 + 志愿者)
  ├─ 任务: 论文 19 个关键任务 (前向选择结果)
  │   ├─ 平地走 (3 速度)
  │   ├─ 静态站立
  │   ├─ 蹲起
  │   ├─ 弓步
  │   ├─ 跳跃
  │   ├─ 侧切
  │   ├─ 坐站
  │   ├─ 上/下楼梯
  │   ├─ 上/下斜坡 (5°)
  │   ├─ 跑步
  │   ├─ 负重走
  │   ├─ 提放重物
  │   ├─ 倒走
  │   ├─ 急停急启
  │   ├─ 转身
  │   ├─ 跨步
  │   └─ 漫步
  └─ 同步记录: G354 IMU + RS02 编码器 + Vicon + 测力台

Phase 2: 便携自采 (IMU Kinematics, 任意场地)
  ├─ 参与者: 10+ 人
  ├─ 任务: 同上 + 非结构化动作
```

### 5.4 OpenSim 处理管线 (用于 Phase 1 的 GT 生成)

```
1. Vicon 数据 → .c3d 格式
2. OpenSim: Scale model (基于参与者身高体重)
3. OpenSim: Inverse Kinematics (标记点 → 关节角度, 200Hz)
4. 测力台数据: 低通滤波 (6Hz, 4阶 Butterworth)
5. OpenSim: Inverse Dynamics (关节角度 + GRF → 关节力矩)
6. 体重归一化: τ_norm = τ_raw / (mass × 9.81)
7. 与传感器时间对齐: 互相关对齐 IMU 和 Vicon 时间戳
```

## 八、力矩映射参数（论文精确复现）

### 8.1 力矩信号处理链

```
τ_estimated(t)
    │
    ├─→ τ_bio = τ_estimated - τ_exo_measured(t-1)
    │       (τ_exo 通过 CAN 读取 RS02 实际力矩反馈)
    │
    ├─→ τ_scaled = τ_bio × α
    │       髋: α = 0.20
    │       膝: α = 0.15
    │
    ├─→ τ_delayed = τ_scaled(t - Δt)
    │       髋: Δt = 100ms (= 10 帧 @100Hz)
    │       膝: Δt = 50ms  (= 5 帧 @100Hz)
    │
    ├─→ Butterworth Lowpass 2nd-order, f_cutoff = 10Hz
    │       (额外延迟 ~25ms)
    │
    ├─→ clamp(τ, -15, 15) N·m
    │
    └─→ CAN MIT Mode: τ_cmd → RS02
```

### 8.2 延时实现

```cpp
// 环形缓冲区实现变延时
struct DelayBuffer {
    std::deque<float> buffer;
    size_t max_size;
    
    DelayBuffer(size_t delay_ms, size_t hz) 
        : max_size(delay_ms * hz / 1000) {}
    
    float push(float val) {
        buffer.push_front(val);
        if (buffer.size() > max_size) {
            float delayed = buffer.back();
            buffer.pop_back();
            return delayed;
        }
        return 0.0f;  // 缓冲未满时返回零力矩
    }
};

DelayBuffer hip_delay(100, 100);  // 100ms @100Hz = 10帧
DelayBuffer knee_delay(50, 100);  // 50ms @100Hz = 5帧
```

### 8.3 Butterworth 滤波器

```cpp
// 二阶 Butterworth 低通, fc=10Hz, fs=100Hz
// 使用双线性变换预计算系数
struct Butterworth2 {
    // fs=100Hz, fc=10Hz
    // [b, a] = butter(2, 10/(100/2))
    float b0=0.0675, b1=0.1349, b2=0.0675;
    float a1=-1.1430, a2=0.4128;
    float x1=0, x2=0, y1=0, y2=0;
    
    float filter(float x) {
        float y = b0*x + b1*x1 + b2*x2 - a1*y1 - a2*y2;
        x2 = x1; x1 = x;
        y2 = y1; y1 = y;
        return y;
    }
};
```

## 九、执行器力矩控制校准

### 9.1 RS02 MIT 模式力矩精度校准

RS02 通过 MIT 协议接收力矩指令，但实际输出力矩受电流环精度和电机常数偏差影响：

```
校准步骤:
1. 固定 RS02 输出轴（用夹具锁死）
2. 发送一系列力矩指令: [-10, -5, -2, -1, 0, 1, 2, 5, 10] N·m
3. 通过 CAN 读取实际力矩反馈 (MIT 协议的 position/velocity/torque 报文)
4. 线性拟合: τ_actual = k × τ_cmd + b
5. 在控制代码中补偿: τ_cmd_compensated = (τ_desired - b) / k
```

### 9.2 RS02 反驱验证

RS02 的 7.75:1 减速比使反驱成为可能，论文的关键假设是执行器具有**高反驱透明度**：

```
验证测试:
1. RS02 上电但不使能
2. 手动旋转输出轴，感受反驱阻力矩
3. 使能 MIT 模式，发送 0 N·m 指令
4. 快速旋转输出轴，通过编码器测回转速 + 力矩反馈
5. 确认反驱阻尼 < 2 N·m（可接受阈值，AK80-9 约 1-2 N·m）
```
